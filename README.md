# Flprog_RTC_STM32 — адаптер аппаратных часов STM32

Версия: **1.0.1** (ревизия FLProg). Базовая версия: 1.0.0.

## Назначение

Предоставляет C-обёртку над STM32duino/HAL RTC для работы `Flprog_RTC`, в частности `FLProgSystemRTC` при `FLPROG_STM32_ONBOARD_RTC_ENABLED`. **Код STM32 HAL/RT_HW не входит в библиотеку и не менялся.**

Заголовок: `#include "flprogRtcStm32.h"`. Требуется STM32duino Core с поддержкой `HAL_RTC_MODULE_ENABLED`, `backup.h`, `clock.h`, `stm32yyxx_ll_rtc.h`.

## Публичный API

- `bool FLPROG_RTC_init(flprog_hourFormat_t format, sourceClock_t source, bool reset)` — инициализация аппаратного RTC. Значение `true` означает, что календарь инициализирован заново. `false` означает отсутствие первичной инициализации **или** неудачу HAL: диагностику смотрите в `Error_Handler()`.
- `FLPROG_RTC_SetTime(...)` / `FLPROG_RTC_GetTime(...)` — время (формат BIN, не BCD), при чтении `subSeconds` в миллисекундах (если поддерживается `RTC_SSR_SS`).
- `FLPROG_RTC_SetDate(...)` / `FLPROG_RTC_GetDate(...)` — дата, год `0..99`, день недели — формат STM32 HAL.
- `FLPROG_RTC_getPrediv(...)` / `FLPROG_RTC_setPrediv(...)` — предделители RTC (сигнатуры отличаются для F1 и других STM32).
- `FLPROG_RTC_StoreDate()` — только STM32F1, сохраняет дату в backup registers.

## Особенности и меры предосторожности

1. `reset=true` **сбрасывает резервную область (backup domain)** и ранее сохранённое время/дату. Для обычного старта используйте `reset=false`.
2. Источники LSE/LSI/HSE обладают разной частотой. В версии 1.0.1 делители настраиваются *после* выбора источника, иначе 1 секунда могла быть рассчитана неверно.
3. Для STM32 не-F1 после `HAL_RTC_GetTime()` обязательно вызывается `HAL_RTC_GetDate()` для разблокировки теневых регистров; отдельные вызовы пользовательского API остаются прежними.
4. Вызовы `GetTime` и `GetDate` при неудаче HAL оставляют переданные выходные переменные без изменений. При отсутствии `RTC_SSR_SS` миллисекунды не меняются.
5. Перенастройка источника RTC во время работы и сохранение даты при такой смене **требуют аппаратной проверки**: поведение backup domain зависит от серии STM32 и STM32duino Core.
6. На некоторых HAL доступны только отдельные делители HSE; недостижимые частоты возвращают ошибку вместо обращения к неинициализированным настройкам.
7. `Error_Handler()` из STM32duino может прерывать выполнение; полноценную обработку его ошибок библиотека не реализует. Поведение функции `FLPROG_RTC_init()` при ошибке не стоит трактовать только по `false`.
8. Для аппаратной проверки нужны тесты как холодного старта, так и старта без `reset`, затем перехода через полночь, восстановления после питания от VBAT и (при необходимости) смены частоты.

## Состав пакета

- `src/` — исправленная реализация и публичный заголовок;
- `keywords.txt` — подсветка имен типов, функций и констант;
- `extras/revision-tests/` — автономный HAL mock, не заменяет сборку STM32/Arduino.
- `CHANGELOG_FLPROG.md`, `AUDIT_FLPROG.md` — изменения и ограничения.
